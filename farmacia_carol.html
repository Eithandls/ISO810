¿Cómo funciona este Trigger de Integración?

Al guardar una factura en la tabla FACTURAS, el disparador evalúa el campo condiciones_pago:
• Si es CRÉDITO ➔ El trigger extrae automáticamente el ID de Factura, ID de Cliente, Fecha y Monto e inserta la deuda en CUENTAS_POR_COBRAR.
• Si es CONTADO ➔ No genera ninguna deuda. El trigger evalúa la condición, la ignora y no guarda nada en Cuentas por Cobrar.

Código del Trigger para Defender en la Práctica

PL/SQL nativo de Oracle

Este es el código exacto implementado en el archivo farmacia_carol_db.sql. Se trata de un disparador AFTER INSERT que se activa automáticamente por cada fila insertada en la tabla FACTURAS: 

CREATE OR REPLACE TRIGGER TRG_FACTURA_A_CXC
AFTER INSERT ON FACTURAS
FOR EACH ROW
BEGIN
    -- Si las condiciones de pago indican que es a CRÉDITO:
    IF UPPER(:NEW.condiciones_pago) = 'CREDITO' THEN
        
        -- Lee los datos de la factura e inserta automáticamente la deuda en Cuentas por Cobrar:
        INSERT INTO CUENTAS_POR_COBRAR (
            id_cxc,
            id_factura,
            id_cliente,
            fecha_cxc,
            monto_deuda,
            estado
        ) VALUES (
            SEQ_CXC.NEXTVAL,
            :NEW.id_factura,
            :NEW.id_cliente,
            :NEW.fecha_emision,
            :NEW.monto_total,
            'PENDIENTE'
        );

    -- Si la factura es de CONTADO, el trigger evalúa la condición, no hace nada
    -- y no genera ninguna deuda en Cuentas por Cobrar.
    END IF;
END;
/

1. ¿Por qué es AFTER INSERT?

Porque la tabla CUENTAS_POR_COBRAR referencia el id_factura como clave foránea. La factura debe existir ya registrada en la base de datos para que la relación sea válida.

2. ¿De dónde saca los datos?

Los extrae directamente de la pseudo-fila :NEW de la factura (:NEW.id_factura, :NEW.id_cliente, :NEW.fecha_emision, :NEW.monto_total).

3. ¿Qué pasa si es al Contado?

El bloque IF no se cumple, el trigger finaliza en 0 milisegundos y la tabla de Cuentas por Cobrar permanece intacta.
