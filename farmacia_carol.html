Flujo de Integración — Triggers en Tiempo Real

Automático

Facturación INSERT

Al crear una nueva factura a crédito, el sistema asigna NCF automáticamente via SEQ_FACTURA y un BEFORE INSERT TRIGGER invoca sp_generar_ncf().

⚡→

Trigger AFTER INSERT TRIGGER

TRG_AFTER_INSERT_FACTURA se dispara automáticamente y ejecuta: INSERT en CUENTAS_POR_COBRAR, calcula fecha de vencimiento según días de crédito del cliente, y actualiza el balance del cliente.

→📊

Cuentas x Cobrar AUTO

Se crea el registro CxC automáticamente con SEQ_CXC.NEXTVAL. Al registrar pagos, TRG_AFTER_INSERT_PAGO actualiza saldos, estado de la CxC y la factura original. Un JOB recalcula días de mora periódicamente.

TRG_BEFORE_INSERT_FACTURA

BEFORE INSERT
PL/SQL — Oracle CREATE OR REPLACE TRIGGER TRG_BEFORE_INSERT_FACTURA BEFORE INSERT ON FACTURAS FOR EACH ROW DECLARE v_seq NUMBER; v_ncf VARCHAR2(20); BEGIN -- Obtener siguiente valor de la secuencia SELECT SEQ_FACTURA.NEXTVAL INTO v_seq FROM DUAL; -- Generar NCF automáticamente vía Stored Procedure sp_generar_ncf('B01', v_seq, v_ncf); -- Asignar valores calculados al nuevo registro :NEW.id := v_seq; :NEW.ncf := v_ncf; :NEW.fecha := SYSDATE; :NEW.itbis := :NEW.subtotal * 0.18; :NEW.total := :NEW.subtotal + :NEW.itbis; -- Log de auditoría INSERT INTO AUDIT_LOG (tabla, operacion, registro_id, fecha) VALUES ('FACTURAS', 'INSERT', v_seq, SYSDATE); END; /

TRG_AFTER_INSERT_FACTURA

AFTER INSERT — Integración CxC
PL/SQL — Oracle CREATE OR REPLACE TRIGGER TRG_AFTER_INSERT_FACTURA AFTER INSERT ON FACTURAS FOR EACH ROW WHEN (NEW.tipo_pago = 'CREDITO') DECLARE v_cxc_id NUMBER; v_dias_credito NUMBER; v_fecha_venc DATE; v_balance NUMBER(12,2); v_limite NUMBER(12,2); BEGIN -- 1. Obtener condiciones de crédito del cliente SELECT dias_credito, balance, limite_credito INTO v_dias_credito, v_balance, v_limite FROM CLIENTES WHERE id = :NEW.cliente_id; -- 2. Calcular fecha de vencimiento v_fecha_venc := :NEW.fecha + v_dias_credito; -- 3. Crear registro en CUENTAS_POR_COBRAR (secuencia) SELECT SEQ_CXC.NEXTVAL INTO v_cxc_id FROM DUAL; INSERT INTO CUENTAS_POR_COBRAR ( id, factura_id, cliente_id, monto_original, monto_pagado, saldo, fecha_emision, fecha_vencimiento, estado ) VALUES ( v_cxc_id, :NEW.id, :NEW.cliente_id, :NEW.total, 0, :NEW.total, :NEW.fecha, v_fecha_venc, 'PENDIENTE' ); -- 4. Actualizar balance del cliente UPDATE CLIENTES SET balance = balance + :NEW.total WHERE id = :NEW.cliente_id; -- 5. Verificar límite de crédito IF (v_balance + :NEW.total) > v_limite THEN sp_alerta_credito(:NEW.cliente_id, v_balance + :NEW.total, v_limite); END IF; -- 6. Log de auditoría INSERT INTO AUDIT_LOG (tabla, operacion, registro_id, detalle, fecha) VALUES ('CUENTAS_POR_COBRAR', 'INSERT_VIA_TRIGGER', v_cxc_id, 'Factura ' || :NEW.ncf || ' → CxC creada', SYSDATE); END; /

TRG_AFTER_INSERT_PAGO

AFTER INSERT — Actualiza CxC
PL/SQL — Oracle CREATE OR REPLACE TRIGGER TRG_AFTER_INSERT_PAGO AFTER INSERT ON PAGOS_CXC FOR EACH ROW DECLARE v_saldo NUMBER(12,2); v_estado VARCHAR2(20); v_fact_id NUMBER; v_cli_id NUMBER; BEGIN -- 1. Actualizar monto pagado y saldo en CxC UPDATE CUENTAS_POR_COBRAR SET monto_pagado = monto_pagado + :NEW.monto, saldo = monto_original - (monto_pagado + :NEW.monto) WHERE id = :NEW.cxc_id RETURNING saldo, factura_id, cliente_id INTO v_saldo, v_fact_id, v_cli_id; -- 2. Determinar nuevo estado IF v_saldo <= 0 THEN v_estado := 'PAGADA'; ELSE v_estado := 'PARCIAL'; END IF; -- 3. Actualizar estado de CxC y Factura UPDATE CUENTAS_POR_COBRAR SET estado = v_estado WHERE id = :NEW.cxc_id; UPDATE FACTURAS SET estado = v_estado WHERE id = v_fact_id; -- 4. Actualizar balance del cliente UPDATE CLIENTES SET balance = GREATEST(0, balance - :NEW.monto) WHERE id = v_cli_id; END; /

SP_GENERAR_NCF — Generador de Comprobantes Fiscales

PROCEDURE
PL/SQL — Oracle CREATE OR REPLACE PROCEDURE sp_generar_ncf ( p_serie IN VARCHAR2, p_secuencia IN NUMBER, p_ncf OUT VARCHAR2 ) AS BEGIN p_ncf := p_serie || LPAD(p_secuencia, 8, '0'); -- Registrar en tabla de control NCF INSERT INTO CONTROL_NCF (serie, secuencia, ncf, fecha_uso) VALUES (p_serie, p_secuencia, p_ncf, SYSDATE); COMMIT; END; /

SP_ACTUALIZAR_MORA — Recalcula Días de Mora

PROCEDURE + CURSOR
PL/SQL — Oracle CREATE OR REPLACE PROCEDURE sp_actualizar_mora ( p_fecha_actual IN DATE DEFAULT SYSDATE ) AS -- Cursor para recorrer cuentas no pagadas CURSOR c_cuentas IS SELECT id, fecha_vencimiento, estado FROM CUENTAS_POR_COBRAR WHERE estado NOT IN ('PAGADA', 'ANULADA') FOR UPDATE; v_dias_mora NUMBER; v_total NUMBER := 0; BEGIN FOR rec IN c_cuentas LOOP v_dias_mora := GREATEST(0, TRUNC(p_fecha_actual) - TRUNC(rec.fecha_vencimiento)); UPDATE CUENTAS_POR_COBRAR SET dias_mora = v_dias_mora, estado = CASE WHEN v_dias_mora > 0 THEN 'VENCIDA' ELSE rec.estado END WHERE CURRENT OF c_cuentas; v_total := v_total + 1; END LOOP; -- Registrar ejecución del job INSERT INTO JOB_LOG (nombre, registros_afectados, fecha) VALUES ('sp_actualizar_mora', v_total, SYSDATE); COMMIT; END; /

PKG_FARMACIA_CAROL — Package de Utilidades

PACKAGE
PL/SQL — Oracle Package CREATE OR REPLACE PACKAGE PKG_FARMACIA_CAROL AS -- Tipos TYPE t_aging_record IS RECORD ( rango VARCHAR2(20), monto NUMBER(12,2), cantidad NUMBER ); TYPE t_aging_table IS TABLE OF t_aging_record; -- Funciones públicas FUNCTION obtener_saldo_cliente(p_cliente_id NUMBER) RETURN NUMBER; FUNCTION calcular_itbis(p_monto NUMBER, p_aplica BOOLEAN) RETURN NUMBER; FUNCTION puede_facturar_credito(p_cliente_id NUMBER, p_monto NUMBER) RETURN BOOLEAN; -- Procedimientos públicos PROCEDURE generar_reporte_aging(p_resultado OUT t_aging_table); PROCEDURE cerrar_periodo(p_periodo VARCHAR2); END PKG_FARMACIA_CAROL; /

Secuencias (Sequences)

SEQUENCE
Oracle DDL -- Secuencia para Facturas (genera ID y base para NCF) CREATE SEQUENCE SEQ_FACTURA START WITH 1000 INCREMENT BY 1 NOCACHE NOCYCLE; -- Secuencia para Cuentas por Cobrar CREATE SEQUENCE SEQ_CXC START WITH 3000 INCREMENT BY 1 NOCACHE NOCYCLE; -- Secuencia para Pagos CREATE SEQUENCE SEQ_PAGO START WITH 5000 INCREMENT BY 1 NOCACHE NOCYCLE; -- Secuencia para Notas de Crédito CREATE SEQUENCE SEQ_NOTA_CREDITO START WITH 200 INCREMENT BY 1 NOCACHE NOCYCLE;

VW_ESTADO_CREDITO_CLIENTES — Vista de Crédito

VIEW
Oracle DDL CREATE OR REPLACE VIEW VW_ESTADO_CREDITO_CLIENTES AS SELECT c.id, c.nombre, c.rnc, c.limite_credito, c.balance, ROUND((c.balance / NULLIF(c.limite_credito, 0)) * 100, 1) AS pct_uso, c.dias_credito, (SELECT COUNT(*) FROM CUENTAS_POR_COBRAR cx WHERE cx.cliente_id = c.id AND cx.estado = 'VENCIDA') AS cuentas_vencidas, (SELECT NVL(SUM(cx.saldo), 0) FROM CUENTAS_POR_COBRAR cx WHERE cx.cliente_id = c.id AND cx.estado IN ('PENDIENTE', 'PARCIAL', 'VENCIDA')) AS total_por_cobrar FROM CLIENTES c WHERE c.tipo = 'CREDITO' ORDER BY pct_uso DESC;

VW_AGING_REPORT — Vista Materializada de Antigüedad

MATERIALIZED VIEW
Oracle DDL CREATE MATERIALIZED VIEW VW_AGING_REPORT BUILD IMMEDIATE REFRESH COMPLETE ON DEMAND AS SELECT c.id AS cliente_id, c.nombre AS cliente, SUM(CASE WHEN cx.dias_mora = 0 THEN cx.saldo ELSE 0 END) AS al_dia, SUM(CASE WHEN cx.dias_mora BETWEEN 1 AND 30 THEN cx.saldo ELSE 0 END) AS mora_1_30, SUM(CASE WHEN cx.dias_mora BETWEEN 31 AND 60 THEN cx.saldo ELSE 0 END) AS mora_31_60, SUM(CASE WHEN cx.dias_mora > 60 THEN cx.saldo ELSE 0 END) AS mora_60_plus, SUM(cx.saldo) AS total_saldo FROM CLIENTES c JOIN CUENTAS_POR_COBRAR cx ON cx.cliente_id = c.id WHERE cx.estado NOT IN ('PAGADA', 'ANULADA') GROUP BY c.id, c.nombre;

Justificación Técnica — Tecnología Propietaria

TRG

¿Por qué Triggers para la integración?

Los triggers (disparadores) garantizan que cada factura a crédito genere automáticamente su cuenta por cobrar sin depender de la lógica de la aplicación. Esto asegura integridad referencial activa: no es posible crear una factura sin su correspondiente CxC. Usamos triggers BEFORE INSERT para asignar secuencias/NCF y AFTER INSERT para la integración entre tablas, siguiendo el patrón de propagación automática de eventos en Oracle.

SP

¿Por qué Stored Procedures (PL/SQL)?

Los procedimientos almacenados encapsulan la lógica de negocio crítica directamente en la BD: generación de NCF (sp_generar_ncf), recálculo de mora (sp_actualizar_mora), y alertas de crédito (sp_alerta_credito). Esto reduce el tráfico de red, garantiza la consistencia transaccional, y permite que los triggers invoquen lógica compleja sin exponer la implementación a la capa de presentación.

SEQ

¿Por qué Secuencias (Sequences)?

Las secuencias Oracle (SEQ_FACTURA, SEQ_CXC, SEQ_PAGO) garantizan la generación de IDs únicos y secuenciales sin bloqueos de tabla. Son fundamentales para el control fiscal (NCF) ya que la DGII exige numeración consecutiva e irrepetible de comprobantes. La opción NOCACHE evita saltos en la numeración, crítico para auditoría fiscal.

VIEW

¿Por qué Vistas y Vistas Materializadas?

La vista VW_ESTADO_CREDITO_CLIENTES encapsula la consulta compleja de estado crediticio, mientras que VW_AGING_REPORT como vista materializada pre-calcula el análisis de antigüedad de cartera para consultas rápidas del dashboard. Se refresca bajo demanda con DBMS_MVIEW.REFRESH. Esto separa la complejidad de las consultas analíticas del código de la aplicación.

CUR

¿Por qué Cursores (Cursors)?

El procedimiento sp_actualizar_mora utiliza un cursor explícito con FOR UPDATE para recorrer y actualizar las cuentas por cobrar pendientes. Esto permite procesamiento fila por fila con bloqueo optimista, evitando condiciones de carrera cuando múltiples sesiones acceden a la tabla de CxC simultáneamente.

PKG

¿Por qué un Package (Paquete)?

PKG_FARMACIA_CAROL agrupa funciones y procedimientos relacionados bajo un namespace único: cálculo de ITBIS, verificación de crédito, generación de reportes de aging. Los packages Oracle ofrecen estado de sesión persistente, carga en memoria compartida (SGA), y compilación como unidad, mejorando el rendimiento y la organización del código PL/SQL.
